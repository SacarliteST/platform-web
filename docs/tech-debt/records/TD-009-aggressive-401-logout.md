# TD-009 — Любой 401 от API полностью выкидывает из сессии

Статус: `Backlog`. Приоритет: P2. Контур: Platform.

## Проблема

`shared/http/create-runtime-fetch.ts` на любой ответ `401` вызывает
`clearSession()` → пользователя моментально выкидывает на `/login`, теряя
несохранённое состояние. Один сбойный запрос к Education (например, при
рассинхроне JWT-конфига между Education и IdentityService) обнуляет всю сессию,
даже если основной токен ещё валиден.

Обнаружено на смоуке Phase 3: `GET /api/v1/admin/profiles` вернул 401 из-за
неверных `Identity:Authority` / `Audience` в `Education` dev-конфиге → фронт
разлогинил администратора.

## Что сделать

- Отличать «токен истёк/невалиден» (действительно разлогинивать) от «конкретный
  запрос запрещён/сервис не сконфигурирован» (показать ошибку, не трогать сессию).
  Например: разлогинивать только если `decodeSessionUser(accessToken)` уже даёт
  `null` (истёк), иначе — пробрасывать 401 как обычную ошибку запроса.
- Либо разлогинивать только на 401 от Identityrefresh/`/auth/me`, а не от всех API.

## Готово, когда

Единичный 401 от прикладного эндпоинта показывает ошибку на экране и не сбрасывает
валидную сессию.
